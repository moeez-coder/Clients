## Method (differs from the 2026-11-05 pull)

The first pull paged `/v2/jobs/search`, which costs 1 record per job, including jobs at companies already sourced. A top-up done that way would buy those jobs again. Instead:

1. **Companies:** `POST /v2/company/tam-by-jobs` with the segment filters and a 30-day posting window, paged at 1 record per company. Every company already in an earlier `*-companies.csv` of this segment is skipped. Tech pages the Northeast-HQ TAM first, then the rest, and stops at 1300 new companies.
2. **Open role:** `POST /v2/jobs/company` (`max_results: 1`, same title filters, 30-day window) per new company gives its `open_role` and `jd_summary`.
3. **People:** `POST /v2/search/waterfall-icp-keyword` per new company, with the same cascade and **1 per company** as the first pull. The TAM/SAM read is unchanged (large pool, so 1 hiring manager per company).
4. **Dedupe:** the same rules as the first pull. In addition, the live rows of every earlier open-role snapshot block a lead, whatever its segment, because those people are already in a running campaign.
